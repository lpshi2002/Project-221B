# Contract — 0~3단계 (기준선, MVP, 교차 검증, 반증)

## 범위
- True Detective 사건을 baseline / structured / full 방식으로 풀고 같은 사건 집합에서 비교한다.
- 사용자가 직접 만든 텍스트 사건도 같은 절차로 풀 수 있다(`b221 new`).

## 범위 밖 (이후 단계)
- 과학수사 RAG, 진술·디지털 전문 모듈(4단계), 표·이미지 입력(5단계), 수사 보드 UI(6단계)
- 정답 해설(outcome)과 근거를 비교하는 **근거 정확도** 채점 — 판정자(LLM judge) 설계가 필요하다

## 완료 기준
1. `uv run pytest -q` 통과
2. 사건마다 `verdict.json`이 게이트를 통과하거나, 실패가 채점표에 드러난다
3. `results/`에 방식별 비교표 + 해석(표본 크기 한계 포함)이 있다
4. 사건을 푼 에이전트가 정답에 접근하지 않았다(배정 메시지·폴더 구성으로 보장)
