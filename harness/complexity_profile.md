# Complexity Profile

| 축 | 판단 | 근거 |
|---|---|---|
| 단계 수 | 중간 | 사건당 5단계 + 게이트 + 보고서, 벤치마크는 사건 × 방식 반복 |
| 경계면 | 중간 | 에이전트 산출물(JSON) ↔ 검증기 ↔ 채점기 |
| 품질 모호성 | 높음 | "잘 추리했다"는 정답률만으로는 부족 → 인용 근거·보정도 측정 |
| 실패 비용 | 중간 | 정답 누출·환각 인용이 섞이면 실험 결론이 무효 |
| 세션 길이 | 중간 | 사건마다 새 컨텍스트, 결과는 파일로 전달 |

**레벨: Medium**

## 적용한 장치

- 계약: `harness/contract.md` (이번 단계의 완료 기준)
- 하드 게이트: `b221 validate` — 스키마, ID 참조, 인용 원문 대조, 추리 규칙(모든 선택지 가설, 반대 증거 없는 제거 금지, full의 반론 필수)
- 평가 기준표: 별도 YAML 대신 `b221 score`의 지표가 기준이다(정답률, 첫 시도 인용 불일치율, 게이트 통과율, Brier)
- 정체 시 중단: 게이트 3회, 재배정 1회

## 실행 모드와 모델

- **서브에이전트 모드.** 탐정끼리 소통할 이유가 없고, 소통하면 오히려 사건 간 오염이 생긴다. 파일로만 결과를 넘긴다.
- 개념 문서 6장대로 **단일 탐정 에이전트로 시작**한다. 반론 검사를 별도 에이전트로 나누는 것은 full(자기 반론)과 비교해 점수가 오르는지 확인한 뒤 추가한다.
- 모델은 실행하는 도구의 기본 모델을 상속한다. 추리가 핵심 작업이라 가벼운 모델로 낮추지 않는다. 결과 파일에 실행 모델을 적는다.
